# Pinned native OCR integration evidence

This directory contains **44 small PNGs**, original observed Paddle baselines and provenance JSON—no model weights, archives, environments, logs or training assets. The copied baseline+PNG payload is **420,540 bytes**; `fixture-manifest.json` records each copied file's SHA256/size and original audit-relative source. `model-lineage.json` records original Paddle source pins and previous/new ONNX hashes.

## CI contract (no evidence-related skips)

Run from repository root with an independently assembled complete 15-model native worker stage:

```sh
export VSE_RUN_NATIVE_INTEGRATION=1
export VSE_NATIVE_OCR_ROOT=/absolute/path/to/native-worker-stage
export VSE_NATIVE_LEGACY_EVIDENCE="$PWD/native/ocr/tests/evidence/legacy"
export VSE_NATIVE_MISSING_EVIDENCE="$PWD/native/ocr/tests/evidence/missing"
export VSE_NATIVE_DETECTION_EVIDENCE="$PWD/native/ocr/tests/evidence/detection"
python -m pytest tests/test_native_ocr_integration.py -v
```

The stage must include native executable, native runtime dependencies, **all 15 models**, deterministic configs and matching model manifest. Tests activate their existing import guard and forbid Paddle/PaddleX/PaddleOCR/Python ORT imports. Evidence paths must be exported on all native OS jobs; do not allow a missing variable to turn parity into a skipped test.

- `legacy/`: 48 detector→crop→recognizer cases, eight legacy models × small/medium detector × script/blank/wide. Conversion manifest deliberately preserves the original historical missing entries; `present` filters the eight actually observed models.
- `missing/`: 18 equivalent cases for the three newly retrieved official ta/te/ka models; KN and KA are existing **Kannada** aliases, not Georgian.
- `detection/`: 22 real production `SubtitleDetect` results (two tiers × 11 fixtures). It intentionally loads PNGs from **its parent `fixtures/`**. Both actual direct detector instances used resize **960/max**, max side 4000, DB thresh .2, box thresh .45, unclip 1.4. Do not replace these with the OCR pipeline's 64/min defaults.

## How the images and goldens were produced

Images are deterministic synthetic text fixtures, plus genuinely decoded frames from deterministic AV1/multiline test videos. They test implementation equivalence, not language accuracy. CI consumes committed PNG bytes; it must not regenerate goldens using the implementation under test.

### Legacy and recovered-language PNGs

Pillow renders 42-pixel fonts onto white RGB images, black text at `(5, 0)`, height 64. `script` width 950 contains the phrase below; `blank` width 320 is empty; `wide` width 2200 repeats the phrase separated by a space. The original generation also had narrow/ASCII recognition-only probes, but those unused PNGs are deliberately excluded here.

Pillow's RAQM support was enabled for shaped scripts. Rendered RGB arrays were reversed to BGR when passed to OpenCV/Paddle. Font/rendering versions can change pixels, so exact PNG SHA—not rerendering—is the regression input contract.

Baselines were obtained from real `backend.tools.ocr.OcrRecogniser` with exact local official models, CPU FP32, batch size 6, fast/accurate modes. The original `pipeline-comparison.json` files are copied **byte for byte**, including both original Paddle and original ORT results. Arabic goldens follow production `bidi.algorithm.get_display` semantics; native logical-order output needs the existing adapter's display conversion.

### Shared 11 detection PNGs

Five 1000×240 black RGB images render 48-pixel repository `NotoSansCJK-Bold.otf` text at `(60, 70)` in white: `Hello world`, `中文字幕测试`, `こんにちは世界`, `Hello world 字幕测试`, and blank. Six frames at 0.5/1.5/2.5 seconds were extracted from the actual AV1 regression clip and multiline clip generated by `scripts/e2e_av1.py` / `scripts/e2e_multiline.py`. The AV1 test transcodes `e2e_smoke.generate_video` with libaom-av1 (CRF 28, cpu-used 8, two threads); PNGs are decoded frames, not a mock AV1 decoder. A separate video-to-SRT integration test still exercises actual codecs end to end.

The direct detection golden was measured by instantiating real production `SubtitleDetect('ch', 'fast'/'accurate')` with `VSE_OCR_BACKEND=paddle`, offline models, CPU hardware. Actual preprocessing/postprocessing object attributes are preserved in the JSON. It was not derived by rescaling OCR boxes.

## Explicit new-graph lineage

Eight legacy ONNX files were originally produced with Polygraphy folding. The reproducible model job now explicitly uses optimizer **None**; their new hashes differ, but original Paddle weights do not. Four V6 and three recovered-model ONNX hashes are unchanged. `model-lineage.json` makes this distinction explicit. The new 15-model build passed 88 OCR fixture cases against the **unchanged** Paddle and older ORT goldens; see model-assets `validation-summary.json`. Do not edit baseline expected outputs merely to accommodate a graph change.
